# Pet Phase 6 修复优化任务拆分（P0-P2）

## 输入依据

- 综合审计：2026-05-08 对 S1-S6 的源码级完成度审计
- 专项审计：S3 跨端同步、S4 商店闭环、S5 繁育经济闭环
- PRD 基线：`docs/PRD_PET_PHASE6_PLAN.zh-CN.md`

## 目标

把当前“桌面端明显领先、Web/Mobile 多为简化版、部分对外叙述高于真实完成度”的状态，拆成可执行的 P0-P2 修复优化任务。

## 优先级定义

- P0：对外承诺已失真，或核心用户链路不闭环，必须优先修复
- P1：底座已存在，但完成度明显不足，影响体验和 PRD 对齐
- P2：增强、补完、长期演进，不阻断当前主流程

## 不重复立项的已完成底座

- S1：桌面独立桌宠窗口、漫游、拖拽、基础交互、VRM/Rive/fallback 渲染链已存在
- S2：后端主动陪伴引擎、桌面端气泡、ack/dismiss/mute 基础能力已存在
- S3：后端 presence 转发链、桌面端 socket 消费链已存在
- S4：成就、时光相册、皮肤安装/激活、基础市场列表能力已存在
- S5：繁育 invite/accept/hatching/hatch 生命周期与桌面端面板已存在
- S6：`/marketplace/skins` 兼容路由重定向已落地，但仍属最低限修补

## P0 — 必须先修的闭环缺口

| ID | 涉及 Sprint | 任务 | 主要动作 | 验收标准 |
|---|---|---|---|---|
| P0-1 | S3 | 统一宠物实时事件契约 | 扩展 shared pet/presence 类型，统一 `presence:pet.*` 事件枚举、payload、客户端解析层，消除桌面独享硬编码 topic | Desktop/Web/Mobile 使用同一套 typed contract；新增 topic 不再三端各写一遍字符串 |
| P0-2 | S3 | Web/Mobile 接入真实实时同步 | 为 Web 与 Mobile 增加 presence socket client，把 `pet.state`、`pet.energy`、`pet.achievement.unlocked`、`pet.breeding.*`、`pet.skin.changed`、`pet.soul.changed` 接进宠物中心/衣柜/繁育页 | 桌面或后端触发宠物事件后，Web/Mobile 在 1s 内自动刷新，无需手动 reload |
| P0-3 | S4 | 商店支付闭环实化 | 废弃“前端确认价格 + `acknowledgedPriceCents` 安装”的伪支付链路，改为真实 checkout/payment intent/order record，安装动作只能由支付成功回调驱动 | 付费皮肤不能绕过支付直接 install；免费皮肤仍可一键安装 |
| P0-4 | S4 | 商店试穿到激活的统一闭环 | 把列表、详情、试穿、安装、激活、渲染刷新合并成一条统一链路；桌面端移除 iframe 外挂市场退路 | 用户在 Desktop/Web/Mobile 均可完成“预览 -> 安装 -> 激活 -> 外观立即变化” |
| P0-5 | S5 | 迷你游戏/繁育资源闭环 v1 | 给小游戏接上真实能量或资源奖励；给繁育 invite/accept/hatch 接上成本、失败态与账务记录 | `energyAwarded` 不再恒为 0；每次繁育有可审计成本与状态变更记录 |
| P0-6 | S6 | 套餐 gating 服务器权威化 | 把灵魂、皮肤、商店、繁育的可用范围、数量上限、升级提示统一下沉到后端，前端只消费 gate metadata | Free/Pro/Pro+ 在三端行为一致，且“已解锁资产可回访”规则明确 |
| P0-7 | S3/S4/S5 | 新增跨端验收测试 | 增加 presence 合约测试、付费安装 E2E、繁育生命周期 E2E，覆盖 Desktop/Web/Mobile 至少一条主链 | 若 topic 漂移、支付被绕过、繁育状态不一致，CI 能直接失败 |

## P1 — 已上线但明显不完整的能力

| ID | 涉及 Sprint | 任务 | 主要动作 | 验收标准 |
|---|---|---|---|---|
| P1-1 | S1 | 桌宠交互规范对齐 | 修正 dock restore 单击/双击语义、语音/聊天/长按行为与 PRD 对齐；补 `monitor_index` 与窗口移动 easing | 桌宠交互文档、桌面行为、测试断言三者一致 |
| P1-2 | S1 | 桌面真实交互 E2E | 为点击、拖拽、吸附、恢复、菜单入口建立真实 E2E，而不只停留在 smoke/wiring | 能自动验证 drag/dock/menu，不再只靠人工 sanity check |
| P1-3 | S2 | Web/Mobile 主动陪伴 UI 补齐 | 给 Web/Mobile 提供主动陪伴 inbox/bubble、ack/dismiss/mute 与偏好设置，不再只有桌面端可见 | 三端都能收到并处理 proactive 事件 |
| P1-4 | S2 | 主动陪伴策略补完 | 补生日、情绪追踪、解锁矩阵联动、去重与频控可观测性，去掉 placeholder 级候选项 | 候选事件可解释、可追踪，且不再有“占位但未真正可用”的策略 |
| P1-5 | S3 | 重连/补拉/冷启动 hydration | 为 Web/Mobile/桌面补上 reconnect、missed-event refetch、last-known-state hydration | 应用从后台恢复或网络闪断后，不需要手工刷新即可回到正确状态 |
| P1-6 | S4 | 成长可视化 v2 | 补进化预览、形态预览、成长阶段说明、全量成就/相册聚合卡片，消除当前 dashboard 过简问题 | S4 不再只是数字面板，而是完整成长视图 |
| P1-7 | S4 | 商店卖家工具三端补齐 | 把可见性、定价、审核状态、版税预览从“部分 Web 可用”扩到 Desktop/Mobile 可操作 | 创作者能在三端管理皮肤上架，而不是只在少数页面可用 |
| P1-8 | S5 | Web/Mobile 迷你游戏真可玩 | 去掉随机分数 quick play 壳层，补真实交互、反作弊 telemetry、结果动画 | Web/Mobile 不再只是随机上报分数按钮 |
| P1-9 | S5 | 繁育展示与揭晓体验 | 增加蛋详情、孵化倒计时、幼崽揭晓页、血统树视图、双方结果对照页 | 繁育从“表单 + 列表”升级为完整体验流程 |
| P1-10 | S6 | 兼容路由与 PRD 对齐测试 | 为 `/marketplace/skins`、公开卡片、商店详情等兼容路径补 contract test，避免只靠 redirect 维持表面可用 | PRD 引用路径与实际路由不会再次漂移 |

## P2 — 长线增强与收尾

| ID | 涉及 Sprint | 任务 | 主要动作 | 验收标准 |
|---|---|---|---|---|
| P2-1 | S1 | 动作与动效精修 | 补更自然的漫游路径、停留点策略、屏幕边界行为、多显示器策略、动画过渡质量 | 桌宠“像活物”的观感提升，不影响核心功能 |
| P2-2 | S2 | 主动陪伴个性化增强 | 引入更多用户画像、作息、任务上下文、最近情绪/记忆作为触发条件 | proactive 命中率与相关性提升 |
| P2-3 | S3 | 实时事件历史与回放 | 增加轻量 timeline / event history，方便定位状态漂移与客服排障 | 用户和 QA 能看到最近 pet 事件流 |
| P2-4 | S4 | 商店发现与推荐 | 增加搜索、筛选、榜单、创作者主页、相关推荐、收藏/稍后购买 | 商店从资产安装页升级为可运营商城 |
| P2-5 | S5 | 繁育经济链上化（可选） | 若产品决定走链上资产，再接 NFT mint、token metadata、交易凭证与链上归属 | 链上与非链上方案二选一，不再混合表述 |
| P2-6 | S5 | 远程拜访/抚摸/共玩 | 基于公开宠物页与 presence 增加 remote visit、touch、feed、co-play 等社交动作 | “社交繁育”扩展为真实社交宠物生态 |
| P2-7 | S6 | Wear OS 轻量桌宠 | 以 glance/tile/complication 形式实现最小可用宠物状态、提醒与快捷交互 | S6.3 从 stub 变成可演示版本 |
| P2-8 | S6 | 公开宠物主页增强 | 强化公开宠物卡片的 lineage、成就、成长时间线、分享素材与社交入口 | 公开页不仅能看，还能承担传播与社交承接 |

## 建议执行顺序

### 第一波：先把“说有但其实没闭环”的部分补齐

1. P0-1 / P0-2：统一实时契约并接通 Web/Mobile
2. P0-3 / P0-4：把商店从“确认框 + 安装”升级为真实交易闭环
3. P0-5 / P0-6：把资源循环和套餐 gating 做成服务器权威逻辑
4. P0-7：补跨端验收测试，防止后续回归

### 第二波：补体验完整度

1. S1 交互规范与桌面 E2E
2. S2 主动陪伴三端补齐
3. S4 成长可视化与卖家工具
4. S5 真小游戏与繁育揭晓体验

### 第三波：做可选增强与长期收尾

1. 商店运营能力
2. 远程社交宠物玩法
3. Wear OS 轻量版
4. 链上资产化（仅在产品决策确认后）

## 一句话结论

当前最该做的不是继续堆新面板，而是优先修正 S3/S4/S5/S6 的“闭环和真实度”，先把跨端同步、商店支付、资源循环、套餐 gating 做实，再回头补 S1/S2 的体验精修和 S6 的长期增强。
