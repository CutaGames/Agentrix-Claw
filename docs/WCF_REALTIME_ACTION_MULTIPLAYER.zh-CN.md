# 路径 A:权威 game server 支持实时动作类联机 — 评估 + 落地

> 目标:支持实时动作类多人(射击/竞速/弹球等)。回合制(五子棋,路径 B)用 /aeon 转发即可;
> 实时动作必须**服务器权威 + 固定 tick 模拟**。本文给架构、已落地的最小证明、以及扩展与成本。

## 为什么回合制够用、实时动作不够
- 回合制(/aeon 路径 B):客户端发"走子",服务器转发,各端本地应用。低频、无连续物理,转发即可。
- 实时动作:有连续物理(球/角色移动/碰撞)、需要**单一权威态**防作弊与不一致。客户端不能各报位置
  (会漂移/作弊),必须:**客户端发输入 → 服务器固定 tick 模拟权威世界 → 广播快照 → 客户端渲染(可插值)**。

## 已落地的最小证明:权威 Pong(server-authoritative)
新增 `backend/src/modules/arcade/`:
- **`/arcade` 网关**(Socket.IO,JWT 握手,与 /aeon 同 secret)。事件:`arcade:join` / `arcade:input` /
  `arcade:restart` / `arcade:leave`,服务器广播 `arcade:state`。
- **`PongRoomService`**:每房间一个 **30Hz 固定 tick 循环**,服务器拥有球/拍/分数,模拟移动+墙/拍碰撞+
  击球角度+得分+胜负(11 分)。客户端只发拍子方向输入(-1/0/1)。座位:先到=左、次到=右、其余观战。
  无人则停循环删房。
- 协议 SSoT:`shared/types/arcade.ts`(虚拟球场 200x120,逐 socket 快照含本端座位 `you`)。
- 前端:`src/services/arcadeRealtime.ts`(连 /arcade,发输入,收快照)+ `src/screens/world/PongRoom.tsx`
  (拖动/▲▼ 控拍,渲染权威快照)。GameRunner 见 bundle `engine==='mp-pong'` 即渲染 PongRoom。

这是**真·实时动作联机**:两端各控一拍,球的物理只由服务器算,谁都改不了球(权威)。

## 这套骨架如何扩展到更复杂动作游戏
保持"输入→tick 模拟→快照广播"骨架不变,只换 `simulate()` 与 input/state 形状:
- **顶视竞技/射击**:state 加实体列表(玩家/子弹/血量),input 加移动向量+开火;tick 做移动/命中判定。
- **竞速**:state 加车辆位姿/速度,input 为油门/转向。
- **网络优化(玩家变多/延迟敏感时再做)**:
  - 客户端预测 + 服务器和解(client-side prediction & reconciliation):本地先动,收到权威态再纠正。
  - 实体插值(渲染滞后 ~100ms 插值)消除抖动。
  - 增量快照 / AOI(只发可见区域)/ 二进制编码 降带宽。
  - 输入序号 + 丢包重传策略。
  本期 Pong 用"全量快照 + 仅在方向变化时发输入",小房间足够顺;上述优化按需加。

## 成本与扩展(诚实)
- **计算**:每活跃房一个 tick 定时器(30Hz)+ 模拟。Pong 极轻;复杂动作(多实体/物理)CPU 随实体数涨。
  单 PM2 fork 可承载数十~上百个轻量房;重模拟或高并发需多进程/多机 + 房间分片。
- **带宽**:快照广播 = 快照大小 × tick率 × 房内人数。Pong 快照 ~100B、30Hz、2-4 人 ≈ 每人 ~3KB/s(很小)。
  复杂动作快照更大,需增量/二进制/降 tick(如 15-20Hz)+ 插值。
- **多实例**:当前内存态单实例权威。要水平扩展需:按 roomId 分片到固定实例(sticky)或把房间状态外置
  (Redis/专用 game server 进程)。建议**按 game server 进程池 + 房间路由**,而非塞进主后端(隔离 tick 抖动)。
- **防作弊**:服务器权威已挡"改位置/改球";仍需校验输入频率/合法性、加速度上限等(动作游戏的常规)。
- **延迟**:同区域玩家 RTT 低体验好;跨区需就近 game server 节点(类似 RTC 的边缘部署)。

## 建议路线
1. **现在(已完成)**:权威 Pong 作为骨架与可玩证明,验证 netcode + 运维形态。
2. **下一步(按需)**:抽出 `GameRoom` 抽象(input/simulate/snapshot 接口),在其上加 1 个顶视竞技小游戏
   (如 2 人坦克/射击),并加客户端预测+插值。
3. **规模化**:把 arcade 拆成独立 game server 进程池 + 房间路由(避免 tick 抖动影响主 API),
   按区域就近部署;高并发再上增量快照/二进制协议。

> 一句话:实时动作联机的正确形态是"服务器权威 + 固定 tick";我们已用权威 Pong 跑通这套 netcode 骨架,
> 复杂动作只是替换模拟逻辑 + 按需加预测/插值/分片,运维上建议独立 game server 进程池。
